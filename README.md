# RO-Inference-Comp-Action-Chunk-Planner-Raw-Phase-3

Standalone Phase‑3 inference package for the
`pi05_origami_comp_action_chunk_phase3` checkpoint. It is compatible with the
`origami-zenoh-v1` contract in `inferencekit_09_02_2026` and does not depend on
the Phase‑1, Phase‑2, DINO, OOI, or checkpoint-planner runtimes at inference.

The fixed runtime path is:

1. Validate the inference-kit observation schema.
2. Resize head-left and both wrist images to `224×224` with bilinear resize.
3. Split each required deform tactile grid into ten tactile images and resize
   each to `224×224` with bilinear resize.
4. Use valid complete raw tactile grids when available; otherwise use deform
   tactile only.
5. Supply the 65D state, 60D tactile vector, canonical speed prompt, and the
   fully masked zero planner prefix to OpenPI.
6. Return `float32[25,65]` absolute joint-position actions in radians. The
   checkpoint’s state-anchored delta target is denormalized with the Phase‑3
   asset and converted against current state by the unchanged OpenPI transform.

## Immutable Phase‑3 contract

Do not change these values when packaging the final checkpoint:

| Contract | Required value |
| --- | --- |
| OpenPI config | `pi05_origami_comp_action_chunk_phase3` |
| Action horizon | `25` |
| Training action stride | `1` |
| State/action dimension | `65` |
| Tactile-vector dimension | `60` |
| Camera and tactile crop size | `224`, bilinear resize |
| Planner | disabled; masked zero prefix only |
| Prompt template | `Fold paper into airplane. Speed: {speed}x.` |
| Valid speed values | `ORIGAMI_SPEED=1` or `ORIGAMI_SPEED=2` |
| Norm stats | final Phase‑3 `norm_stats.json` |

`ORIGAMI_SPEED` is mandatory for a server or replay process. It has no
default. Values such as missing, `0`, `3`, `1x`, or `2x` fail before model
loading. The process internally chooses exactly one prompt:

```text
Fold paper into airplane. Speed: 1x.
Fold paper into airplane. Speed: 2x.
```

The client prompt field is accepted for inference-kit compatibility but is
ignored. It cannot override the selected canonical prompt.

`ORIGAMI_PLANNER_ENABLED=true` is rejected. Planner/DINO/OOI assets are not
needed and cannot be enabled at runtime.

## Bundle layout

`model_bundle/bundle.yaml` is the source of runtime paths for Docker. Populate
the bundle before building an image:

```text
model_bundle/
  bundle.yaml
  assets/
    paligemma_tokenizer.model
  configs/
    openpi_comp_action_chunk_runtime.yaml
  weights/
    openpi/
      pi05_origami_comp_action_chunk_phase3/
        params/
        assets/
          competition_paper_reprocessed_origami_comp_action_chunk_phase3/
            norm_stats.json
  dataset_replay/                     # optional Docker replay subset
    episodes/<episode_uid>/...
```

The checkpoint folder must contain both `params/` and the matching Phase‑3
asset. The runtime reads:

```text
weights/openpi/pi05_origami_comp_action_chunk_phase3/
  assets/competition_paper_reprocessed_origami_comp_action_chunk_phase3/norm_stats.json
```

An Excel/CSV export of norm stats is not read by OpenPI. The bundle requires
the machine-readable `norm_stats.json` generated by the Phase‑3 normalization
script.

OpenPI source is vendored under:

```text
vendor/openpi/src/
  openpi/
  openpi_client/
  future_latent_predictor/
```

It includes the Phase‑3 training config and two inference-only compatibility
patches: output unnormalization ignores input-only norm-stat keys, and
`ORIGAMI_OPENPI_PARAM_DTYPE` supports `checkpoint`, `bfloat16`, and `float32`.

### Settings that may be changed

These are safe operational choices, not training-contract changes:

```yaml
# model_bundle/bundle.yaml
runtime:
  device: cuda:0
  precision: fp16

server:
  execution_mode: sync       # or async
  warmup_inferences: 1
  log_inference_every_n: 1   # raise this to reduce request-log volume
```

You may also set these per process:

```text
EXECUTION_MODE=sync|async
ORIGAMI_WARMUP_INFERENCES=1
ORIGAMI_OPENPI_PARAM_DTYPE=checkpoint|bfloat16|float32
ORIGAMI_JAX_MEM_FRACTION=0.60
XLA_PYTHON_CLIENT_PREALLOCATE=false
XLA_PYTHON_CLIENT_ALLOCATOR=platform
```

Do not alter action horizon, action stride, dimensions, prompt template,
planner setting, Phase‑3 config name, or asset ID. If the actual checkpoint
directory name differs, update only this path in
`model_bundle/configs/openpi_comp_action_chunk_runtime.yaml`:

```yaml
paths:
  checkpoint_dir: ../weights/openpi/<actual-checkpoint-directory>
```

## Tactile behavior

Deform tactile is required. Raw tactile is optional as one complete
`uint8[480,1600,3]` grid:

- valid grid with at least one non-zero pixel → pass complete raw + deform;
- some raw tactile tiles zero and others non-zero → still pass complete raw + deform;
- entire raw grid zero → deform-only, `raw_status=all_zero`;
- raw absent → deform-only, `raw_status=missing`;
- raw null, empty, wrong shape, or wrong dtype → deform-only with a diagnostic
  such as `raw_status=null`, `empty`, or `invalid`.

Malformed raw tactile does not reject a request. Missing/invalid deform tactile,
required cameras, state, joint torque, or 60D tactile vector does reject it.

The public schema still requires head-left, head-right, left wrist, right
wrist, deform tactile, 65D state, 65D joint torque, and 60D tactile vector.
The Phase‑3 checkpoint uses head-left and both wrists; head-right is retained
and validated to preserve inference-kit compatibility.

## Add replay episodes

To replay inside Docker, copy a small raw subset to:

```text
model_bundle/dataset_replay/episodes/<episode_uid>/
  arrays/state_65d.npy
  arrays/action_65d.npy
  arrays/tactile_60d.npy
  arrays/timestamps.npy       # optional
  arrays/frame_index.npy      # optional
  videos/head_left.mp4
  videos/wrist_left.mp4
  videos/wrist_right.mp4
  videos/tactile_deform.mp4
  videos/tactile_raw.mp4      # optional for deform_only; required by deform_plus_raw replay
```

Default replay modes are `deform_only` and `deform_plus_raw`. The replay output
includes action MAE/RMSE, training-style loss, raw availability/status,
planner availability (always false), and stage timings. It also displays tqdm
bars for planning, modes, episodes, and samples.

## Entrypoint modes

```bash
docker run --rm -e ORIGAMI_SPEED=1 "$IMAGE" verify-bundle
docker run --rm --gpus all -e ORIGAMI_SPEED=1 "$IMAGE" dataset-replay --dry-run
docker run --rm --gpus all -e ORIGAMI_SPEED=1 "$IMAGE" serve
docker run --rm -it "$IMAGE" bash
```

`serve` additionally requires `ORIGAMI_ZENOH_ENDPOINT` and
`ORIGAMI_SESSION_ID`. `bash`, `sh`, and `python` image entrypoint modes do not
start the model and therefore do not require `ORIGAMI_SPEED`.
